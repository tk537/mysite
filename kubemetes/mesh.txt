# Istio Windows インストールガイド

## 1. 役割と仕組み
- **istioctl.exe**: Windows上で動作するIstio管理ツール。クラスターの診断や設定を行います。
- **Sidecar 注入**: Windowsからコマンドを打つだけで、Linuxノード上のPodにEnvoyプロキシが自動挿入されます。

## 2. インストール手順 (Windows版)

### ステップ1: インストーラーの実行
以下のコマンドで、最新のIstioバイナリをダウンロードし、現在のフォルダに展開します。
[PowerShell]
curl -L https://istio.io/downloadIstio | sh -

### ステップ2: 環境変数 (PATH) の設定
展開されたフォルダの中にある `bin` フォルダを、Windowsの環境変数に追加します。
(例: istio-1.2x.x\bin をシステム環境変数のPathに追加)

### ステップ3: クラスターへのインストール
istioctl install --set profile=demo -y

### ステップ4: サイドカー注入の有効化
kubectl label namespace default istio-injection=enabled

## 3. 動作確認コマンド
istioctl version
kubectl get pods -n istio-system
'@ | Out-File -FilePath "README.md" -Encoding utf8

# Istio Service Mesh & Kustomize 完全解説

## 1. Istio（Service Mesh）の4つの主要な役割
Istioを導入すると、以下の機能をアプリのコード変更なしで実現できます。

- **トラフィック制御（Traffic Management）**:
  カナリアリリース、リトライ処理、タイムアウト設定、サーキットブレイカー（障害の連鎖防止）。
- **セキュリティ（Security）**:
  サービス間の通信を自動的に暗号化（mTLS）。「誰が誰にアクセスできるか」の認可制御。
- **可視化（Observability）**:
  「どのサービスが遅いか」「エラーがどこで出ているか」をグラフやダッシュボードで可視化。
- **レジリエンス（Resilience）**:
  わざとエラーを注入（カオスエンジニアリング）して、システムの耐久性をテスト。

## 2. カナリアリリースの仕組み
- **Sidecar Proxy (Envoy)**: Pod内に通信専用のコンテナを相乗りさせ、通信を横取りして制御します。
- **VirtualService**: 「どの道をどれくらいの割合(%)で通すか」を決める交通標識。
- **DestinationRule**: 「道の先にあるグループ（v1, v2など）」を定義する台帳。

## 3. フォルダ構成

# 3. 確認

# 4. Istio設定（カナリアリリース）の作成
@'
apiVersion: networking.istio.io/v1alpha3
kind: DestinationRule
metadata:
  name: web-app-dr
spec:
  host: web-app-service
  subsets:
  - name: v1
    labels: { version: v1 }
  - name: v2
    labels: { version: v2 }
---
apiVersion: networking.istio.io/v1alpha3
kind: VirtualService
metadata:
  name: web-app-vs
spec:
  hosts:
  - web-app-service
  http:
  - route:
    - destination:
        host: web-app-service
        subset: v1
      weight: 90
    - destination:
        host: web-app-service
        subset: v2
      weight: 10
'@ | Out-File -FilePath "overlays/canary/istio-specs.yaml" -Encoding utf8
